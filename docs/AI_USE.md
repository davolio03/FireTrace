# Use of AI tools

This page answers proposal §11, criterion 10: it declares how the team used AI tools to build FireTrace. AI coding agents helped write code, tests and documentation. The scientific decisions, the approval of every task and the review and merge of every change were made by people.

## What the product does not use

- **No AI at run time.** The pipeline, the API and the web run no language model and call no AI service.
- **No generated evidence.** The Evidence Inspector shows values read from the numerical rasters and caveats computed by deterministic, documented rules ([caveats](methods/caveats.md)). No explanation, value or confidence is generated by a language model.
- **No deep-learning model.** No model was trained or used. The Siamese U-Net experiment (XP-03) was proposed but not carried out.
- **No generated imagery.** Every map layer is rendered from NISAR, Copernicus DEM or Sentinel-2 data by the documented pipeline.

## Tools used to build it

| Tool | Provider | Used for |
| --- | --- | --- |
| Claude Code | Anthropic (Claude models) | Writing pipeline, API and web code with tests, documentation and Kanvas board notes |
| OpenCode | open-source coding agent; the models used were not recorded | Writing web and integration code, tests and board notes |
| Codex (gpt-6.1-sol) | OpenAI | Independent, read-only code reviews before pull requests; its findings were fixed and re-tested before a person reviewed the pull request |
| Engram | open-source memory for coding agents | Shared memory of the team's agreed decisions; it stores text and generates nothing |

The tool list comes from the agent signatures recorded on the Kanvas board (for example `claude-david`, `opencode-frontend`, `codex`). Commits carry no AI attribution trailers, by repository rule, so this page is the declaration.

## How AI work was controlled

- **People decide the science.** The method choices (normalization domain, threshold, smoothing, minimum areas, caveat thresholds, perimeter rasterization) were proposed with their options and agreed by the task owner before implementation. They are recorded in the [methods](methods/) and were never tuned on the comparison with the perimeter.
- **People approve and close tasks.** On the Kanvas board, agents can only propose tasks, start approved ones and submit them for review. A person approves each proposal and marks each task done.
- **People merge.** Agents open pull requests only when asked and never merge. Each pull request goes through the quality gate (lint, tests, build and contract validation) and human review.
- **Results are checked against data.** Every number in the documentation was produced by the pipeline from the real inputs and can be traced to a release file and its sha256 ([limitations](LIMITATIONS.md)). Tests use small synthetic rasters with values computed by hand.
