# Evidence and readiness snapshot

**Documentation baseline: 2026-11-14.** Kanvas remains the only canonical task state. This page describes evidence boundaries, not task progress or new approvals.

| Boundary | What exists | What is not established |
| --- | --- | --- |
| Shared interfaces | v1.2.0 schemas, OpenAPI, fixtures and validator | Full consumer implementation or scientific correctness |
| Development examples | Synthetic radar values/images; supplied reference geometry | Real pipeline results or app integration |
| Case inputs | Proposal reports selected pair, common grid and reference checks | Fresh raster/HDF5 verification by this foundation |
| Product runtime | Agreed stack and module boundaries | Running pipeline, API, web or end-to-end demo |
| Shared memory | `firetrace` identity; Cloud selected | Server deployment, enrollment, replication or team token verification |

Outstanding decisions include human role/reviewer assignments, AOI/rasterization/coverage and robust-normalization details, hosting/budget, provenance completeness and final challenge/source usage rules. Resolve task ownership/state in Kanvas, not this table.

Record actual application/real-data rehearsal evidence in [DEMO](DEMO.md), with revision/artifact identities, commands, exit codes, limitations and fallback. Contract/bootstrap checks alone never make the product scientifically validated or demo-ready.
